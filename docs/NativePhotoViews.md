# LVUI 사진 라이브러리 화면

사진 갤러리는 [System 갤러리 시안](https://www.figma.com/design/PFMgQb3BVbrTbzPPsoWsRp/System?node-id=34-336),
좁은 화면은 [컴팩트 갤러리 시안](https://www.figma.com/design/PFMgQb3BVbrTbzPPsoWsRp/System?node-id=37-85),
정보 시트는 [파일 정보 시안](https://www.figma.com/design/PFMgQb3BVbrTbzPPsoWsRp/System?node-id=34-376)을
기준으로 LVUI로 선언한다. 컴포넌트와 표면 색상은 LVUI 시스템을 사용하며 자체 토큰은
만들지 않는다. QML 갤러리는 실제 소비자를 이전하는 동안 레거시로 격리한다.
정보 시트는 플랫폼별 자동 표시를 명시하여 데스크톱에서는 중앙에, 모바일에서는
모바일 시트 위치에 배치한다.
2026-11-15 macOS 헤드리스 소비자는 선택한 사진의 정보 시트가 중앙에 열리는지 확인했다.

Qt 없는 C++23 프레젠테이션 모델은 앱이 주입한 사진 스냅샷과 변경 이벤트를
받아 안정적인 사진 ID별 행을 제공한다. 미리보기의 주소와 리비전, 선택 및
정보 시트, 활성·작업 중·공유 가능 상태를 분리한다. 행의 부분 갱신은 다른
행을 다시 만들지 않는다. 삭제된 행과 닫힌 화면은 이전 콜백을 무효화한다.
모델과 행의 모든 상태 변경·동작은 생성된 소유 스레드에서만 수행한다. 다른
스레드의 직접 호출은 상태나 주입된 콜백을 읽거나 바꾸기 전에 거부하며,
쿼리 포트는 오류를 반환한다. 호스트는 백그라운드 결과를 소유 실행기로 전달한다.
모델 파괴 시 대기 중인 쿼리를 취소하고 포트를 상태보다 먼저 닫는다. 호스트는
모델을 소유 스레드에서 해제하고, 그 모델의 현재 쿼리가 반환된 다음 파괴해야 한다.
macOS 프레젠테이션 공유 라이브러리는 최종 런타임 검색 경로로 빌드하며, 같은
타임스탬프에서 다시 설치해도 경로가 중복 추가되지 않는지 별도로 검사한다.
초기 동기화와 이벤트 누락 복구는 호스트가 명시적으로 스냅샷을 요청하며,
평상시에는 이벤트로 변경한다.

공유 프레젠테이션 패키지는 동일한 C++ 뷰모델에 접근하는 C ABI와 Python API를
제공한다. Python 호스트는 초기 스냅샷, 항목별 변경, 순서 변경, 선택과 사진 명령을
전달하며 관측 콜백으로 변경된 속성과 행의 안정 ID를 받는다. 알림은 모델 변경 중
동기적으로 발생하므로 전체 스냅샷이 필요한 소비자는 현재 호출이 반환된 뒤 명시적으로
조회한다. 구조와 모델 속성의 알림은 관측을 등록하면 전송하고, 개별 행 속성은
`watch_rows()`에 지정된 안정 ID에 대해서만 구독한다. 등록 해제는 `observe(None)` 또는
빈 행 목록으로 명시한다. 주기적 조회는 시작하지 않는다. Python의 모델 및 네이티브 모델 리스는
생성한 스레드에서 명시적으로 닫아야 하고, 뷰가 모델을 사용하는 동안 리스를 유지하며
현재 콜백과 쿼리가 끝난 뒤 해제한다. 콜백에 전달된 문자열은 콜백 동안만 유효하다.

공유 패키지의 `iiPhotoLibraryPresentation_PYTHON_DIR`에서
`iiphotolibrary_presentation.PhotoModel`을 가져올 수 있다. Python과 공유 라이브러리가
서로 다른 설치 경로에 있을 때 생성자의 `library_path`와 `core_library_dir`를 명시할 수
있다. 예를 들어 다음 코드는 명시적인 이벤트 수신과 사용자의 선택만 처리한다.

```python
from iiphotolibrary_presentation import PhotoModel

with PhotoModel() as photos:
    photos.observe(lambda property_name, row_id: print(property_name, row_id))
    photos.watch_rows(["asset-1"])
    photos.update({"active": True, "access": "ready"}, [
        {"id": "asset-1", "gallery_key": "gallery-1", "name": "Image"}
    ])
    photos.select("asset-1")
```

초기화와 복구용 `update`, 항목 단위 `change`·`remove`, `reorder`, 가시 ID,
파일 드롭, 선택, 확대와 뷰 명령을 제공한다. 저장소 연결·파일 선택·원본 열기 등은
`set_actions()`로 앱이 제공한다. 콜백 예외는 C 경계를 넘어가지 않고 보관되며 다음
Python 호출에서 다시 보고한다. 외부 네이티브 호스트가 모델을 보유하는 동안에는
`lease_model()`을 유지하고 뷰와 진행 중인 쿼리를 먼저 종료한다. 정적 빌드와
WebAssembly에는 Python 모듈을 설치하지 않으며 C++·C API는 별도로 제공한다.
ID로 사진을 선택하는 `selectById()`는 모델의 기존 ID 인덱스를 사용하고 숨김·재진입
제어는 기존 행 선택과 동일하게 적용한다. `findById()`도 같은 인덱스로 행을 찾으며,
행 관측 갱신은 명시적으로 지정된 ID만 확인한다.

2026-11-15 macOS에서 공유 프레젠테이션과 정적 프레젠테이션을 각각 빌드했고,
Python의 부분 알림·행 구독·명령·스레드·콜백 재진입·리스 검사가 통과했다.
별도의 임시 설치 prefix에서 C17 소비자를 빌드하고, 설치된 Python 모듈이 상대 경로로
공유 라이브러리를 찾는 검사도 통과했다. Windows MinGW x86-64에서는 C ABI 구현을
객체까지 교차 컴파일했으며 Windows 링크·실행은 검증하지 않았다. 시스템 설치본은
갱신하지 않았고 실제 사진 앱도 실행하지 않았다.
별도 AddressSanitizer·UndefinedBehaviorSanitizer 빌드에서 C ABI의 콜백 중 모델 파괴와
C++ 모델 검사가 통과했다. 연결된 Core 라이브러리는 계측하지 않았다. 이 macOS
환경에서는 LeakSanitizer가 지원되지 않아 누수 검사는 수행되지 않았다.

라이브러리 연결, 파일 선택, 새로고침, 원본 열기, 복사, 복제, 공유, 휴지통과
가시 영역의 미리보기 우선순위는 호스트가 주입한 명령으로 실행한다. 화면은
파일 대화상자나 운영체제 위젯을 직접 만들지 않는다. 미리보기의 실제 읽기와
디코딩은 앱이 주입한 이미지 서비스의 책임이다. 스크롤과 확대 상태는 iiGUI
뷰포트 입력에 따라 업데이트하고 타이머로 계속 조회하지 않는다.
호스트가 파일 선택의 시작 또는 완료 실패를 표시할 때 사용할 `photo.picker_failed`
문구는 화면과 함께 설치하는 영어·한국어 카탈로그에 포함한다. 오류를 표시하는
시점과 선택 요청의 취소·수명은 각 호스트가 소유한다.

레거시 `PhotoController`에 연결하는 선택적 `iiPhotoLibrary::PresentationBridge`는
기존 서비스의 변경 신호만
관찰하고 화면 명령을 기존 서비스에 전달한다. 앱은 어댑터·뷰모델·LVUI 뷰의
수명을 함께 소유하고, 화면이 숨겨지면 가시 미리보기 우선순위를 비운다.
항목 삽입·삭제는 기존 행 식별자를 검증한 뒤 연속 범위 하나로 적용하며,
정렬은 기존 행의 식별자 순서만 재배치한다. 기존 행 객체와 나머지 메타데이터는
유지한다. 행 개수나 변경 구간의 식별자가 원본과 맞지 않거나 모델이 재설정되면
이벤트 누락 복구를 위해 전체 스냅샷을 한 번 다시 읽는다. 호스트도 `reconcile()`을
명시적으로 호출할 수 있다. 이 검사는 모든 종류의 과거 이벤트 누락을 자동으로
탐지한다고 보장하지 않으며 폴링을 시작하지 않는다.
뷰 활성화가 퇴역하면 가시 키의 빈 알림도 자동으로 전달한다.
앱 런타임 장착, 운영체제 권한 대화상자, 실제 라이브러리와 GPU 출력은 별도
검증으로 구분한다.

`iiPhotoLibraryPresentation` 패키지에는 `iiPhotoLibrary::Presentation`,
`iiPhotoLibraryPresentation_VIEWS_DIR` 및 `iiPhotoLibraryPresentation_STRINGS_DIR`가
있다. Qt 서비스와 연결하려면 별도의 `iiPhotoLibraryPresentationBridge` 패키지를
사용한다. 기존 `iiPhotoLibrary_QML_IMPORT_PATH`는
`iiPhotoLibrary_LEGACY_QML_IMPORT_PATH`의 호환 별칭이며 기존 QML은
`src/Legacy/qml` 및 설치본의 `legacy/qml`에 있다. 기존 QML 호환 검사 전용
하네스도 `tests/Legacy/PhotosHarness.qml`에 격리되어 있다.

기존 제품이 이전 사진 서비스 바이너리를 계속 사용해야 한다면
`src/Presentation/QtCompatibility`를 별도로 구성해 같은 어댑터를
`iiPhotoLibrary::QtPresentationBridge` 패키지로 제공할 수 있다. 서비스를 정적으로
링크하는 제품은 브리지도 정적으로 링크해 `PhotoController` 복사본이 둘 생기지
않게 한다. 공유 브리지는 명시적인 공유 사진 서비스에서만 허용한다. 같은 어댑터가
포함된 새 `iiPhotoLibrary::PresentationBridge`와 이 호환 패키지를 함께 링크하지
않으며, 서비스 헤더와 바이너리 및 Core ABI는 각 제품이 일치시켜야 한다.
기존 서비스의 모델 재설정은 다음 이벤트 턴에 명시적인 스냅샷으로 복구하고,
새 서비스의 개별 삽입·삭제 이벤트에 대한 즉시 부분 갱신 계약은 유지한다.
Society가 빌드에 사용하는 기존 정적 사진 서비스와 같은 Core ABI의 모델을 조합한
브리지 및 별도 설치 스테이징 소비자 검사에서 변경, 순서, 미리보기 무효화와
재진입·종료를 검증했다. 이 검사는 실제 사진 라이브러리나 앱 화면을 열지 않는다.

기본 테스트는 기존 사진 서비스와 설치 소비자 검사를 유지하면서 Qt Quick과 LVRS를
요구하지 않는다. 레거시 QML의 두 갤러리 검사는
`IIPHOTOLIBRARY_TEST_LEGACY_QML=ON`을 지정했을 때 별도 테스트로 추가된다.
새 LVUI 화면의 동작은 아래의 독립 소비자 검사에서 검증한다.

현재 갤러리의 C++ 모델과 Qt 서비스 어댑터는 항목 선택·부분 변경·수명 종료를
헤드리스 테스트한다. 최초 데이터가 도착하면 최신 항목을 드러내고, 이후 목록
변경은 사용자의 탐색 위치를 유지한다. 앱 호스트는 화면을 숨길 때 `hide()`,
다시 보일 때 `show()`를 호출하여 우선순위를 비우고 최신 위치로 재진입한다.
뷰포트 폭과 높이는 기본적으로 0으로 두어 호스트 배치에 맞추며, 호스트가 필요한
축만 명시적인 논리 픽셀 크기로 지정할 수 있다. 갤러리 폭이 기존 화면과 같은
600 논리 px 미만이면 가져오기·추가·새로고침을 세로로 놓는다. 배치 크기가 실제로
바뀔 때만 이벤트를 받아 전환하며 폴링하지 않는다.
크기 슬라이더는 기존 확대 범위인 56–400 논리 px를 관측 가능한 썸네일 크기에
양방향 연결해 포인터·키보드·접근성 명령으로 갤러리 크기를 조절한다. 갤러리의
터치 핀치도 iiGUI 이벤트를 받아 같은 크기 범위에 적용하며 숨긴 화면에서는 거절한다.
핀치 중심의 사진과 행 내 상대 위치는 열 수가 달라져도 가능한 한 같은 지점에 유지한다.
보조 클릭은 해당 행에 붙인 LVUI ContextMenu를 열며, 열기·복사·복제·공유·삭제를
다른 선택 행과 무관하게 그 사진의 ID로 전달한다. 메뉴가 열리면 정보 시트를 열지
않고 해당 사진을 선택한다. 숨겨지거나 제거된 행은 이후 명령을 전달하지 않는다.
터치 길게 누르기도 iiGUI의 컨텍스트 메뉴에 연결되며, 헤드리스 검사에서 선택한
사진의 메뉴만 열리고 일반 탭은 발생하지 않는지 확인한다. 가로 드래그는 기존과
같이 누르기 시작 시점에서 180 논리 px 이동을 두 배 확대에 대응하고 누른 사진의
상대 위치를 유지한다. 확대 한계에 닿은 뒤 되돌릴 때도 최초 크기와 누적 이동을
기준으로 판정한다.
드래그가 시작되면 사진 선택은 취소하며 일반 클릭과 세로 스크롤은 유지한다.
파일 정보에는 시안과 기존 화면처럼 유형·크기·생성 시각의 이름과 값을 표시한다.
크기는 원본 바이트 수를 유지하면서 1024 단위와 번역 가능한 단위 문자열로 표시하고,
유효한 시간대가 포함된 ISO 시각은 사용자 기기의 현지 시각으로 변환한다. 알 수 없는
시각 형식은 원본 문자열을 보존한다. 화면에서 쓰는 레이블·단위는 카탈로그로 공급하며,
언어나 선택한 항목이 변경될 때 관련 텍스트만 갱신한다.
Society macOS 소스는 기존 사진 서비스와 이 뷰를 iiGUI 표면에 연결한다. 기존
서비스·브리지·생성 뷰를 모의 페인트 장치로 조합한 검사는 사진 선택과 변경·삭제를
확인한다. 실제 앱 창이나 GPU 출력, 핀치·드래그·길게 누르기의 실제 기기 입력 및
나머지 운영체제의 앱 호스트는 검증하지 않았다.
Society의 Windows 데스크톱 소스 구성에도 같은 LVUI 뷰와 사진 서비스를 연결했으며,
표면·입력의 실제 Windows 제품 링크와 실행은 아직 검증하지 않았다.
기존 Qt 사진 서비스의 미리보기는 `previewStamp`가 준비된 경우에만 LVUI에

준비되면 다시 공개한다. 이 규칙은 해당 서비스 어댑터의 계약이며 네이티브
`PhotoEntry`가 리비전 없는 주소를 사용하는 것을 제한하지 않는다.
호스트는 `previewChanged`를 이미지 로더의 무효화에 연결한다. 행의 새 주소,
새 리비전 또는 재삽입된 주소는 화면의 관측 가능한 값이 바뀌기 전에 무효화한다.
하나의 스냅샷이나 행 묶음에서 같은 주소는 한 번만 무효화하며 변경 없는 정보
갱신은 무효화하지 않는다. 이 처리는 사진 서비스의 변경 통지 또는 명시적 복구
조회에만 반응하고 별도의 주기적 검사나 이미지 읽기를 시작하지 않는다.
